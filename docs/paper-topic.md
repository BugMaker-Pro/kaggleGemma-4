## 3. 核心：把三个数分开

论文的全部论证压在把这几件事分开上。混在一起就会写成「我们建了个图」：

| # | 概念 | 定义 | 实测 |
| --- | --- | --- | --- |
| A | **文件级 recall@10** | 同一份排序按文件去重后，黄金文件被找到的比例 | **62.4%** |
| B | **符号级 recall@10** | 黄金符号被找到的比例 | **27.5%** |
| C | **候选池召回**（top-200 BM25） | 黄金符号有多少进了池子 | 60.0% |
| D | **一跳可达（5 种子）** | 黄金符号有多少是 top-5 种子的邻居（**不含种子自己**） | **11.9%**（2 跳 35.7%） |
| E | **oracle@10** | 完美重排（池 + 种子邻居）能到多少 | 63.0% |

三个可以直接写进摘要的推论：

1. **A/B = 2.3**：文献里「文件级 92.7%」那种数字不是终点，只是换了个更粗的刻度；真正的空白在符号级。
2. **可达不等于能用**：一跳只碰到 11.9%，但二跳能到 35.7%——**半径一放大，可达率涨三倍**，可是二跳臂照样输（−0.026）。所以瓶颈不是「够不到」，是**够到了也排不进前 10**（邻居绝大多数不是答案）。
   这条比原来的「22.1% 是天花板」更准，也更难被反驳：它承认可达率能涨，同时指出涨了也没用。
3. **B/C = 0.46**：黄金符号能进池子的一半多一点；剩下的丢在名字匹配上。

## 4. 方法与已交付的代码

全部 stdlib、纯 CPU、单机可跑；300 任务全量 27 分钟（6 进程）。

```powershell
$py = 'D:\pyenv\cpython-3.12.13-windows-x86_64-none\python.exe'
& $py experiments\gold.py --tasks data\swebench_lite.jsonl --out data\gold_symbols.jsonl --snapshots data\repos
& $py tools\run_experiment.py --jobs 6 --pool 200
& $py tools\analyse.py
```

| 模块 | 作用 |
| --- | --- |
| `experiments/patchfile.py` | 解析 unified diff，给出变更行锚点（删行锚自己，增行锚 `old_line-1`） |
| `experiments/symbols.py` | `ast` 抽符号；行号 → 最内层符号 |
| `experiments/snapshot.py` | 不落盘读 tar；`read_all_text` 单次解压（gzip 不能回退，逐文件读会变成 N 次全解压） |
| `experiments/gold.py` | E0：黄金符号 + 显式记录解析不了的锚点 |
| `experiments/buildgraph.py` | 建图器，输出与官方 graph **同 schema**（`nodes[id,name,text]` / `edges[source,target,type,key]`） |
| `experiments/retrieve.py` | BM25 + 四种图策略 + 字符预算计费 |
| `experiments/coverage.py` / `evalcov.py` | 覆盖率四分类（自检用，见 §5 警告） |
| `tools/analyse.py` | 配对差值、bootstrap CI、符号检验、分仓库表 |

**建图器的边分七种解析状态**，这是论文的第二个交付点——大多数工具把它们折叠成一条「边」：

`local` / `import` / `unique` / `suffix` / `external`（stdlib 或三方依赖，不是缺陷）/ `ambiguous` / `unresolved`

django 一个快照实测（2,715 文件 / 38,651 节点 / 209,502 边 / 10.8 s）：

| 状态 | 边数 | 占比 |
| --- | ---: | ---: |
| unresolved | 71,436 | 34.1% |
| local | 40,257 | 19.2% |
| import | 32,648 | 15.6% |
| ambiguous | 31,514 | 15.0% |
| unique | 23,365 | 11.2% |
| external | 10,282 | 4.9% |

**只有 46% 的调用点能在仓库内解析到确定目标。** 这个数字独立可引用。

## 5. 结果（300/300 任务，2026-10-25）

**四条图策略，全部在同候选池、同上下文字符预算下配对比较（n=290）：**

| 臂 | 做法 |
| --- | --- |
| `text` | BM25 top-10（基线） |
| `graph_rerank` | 在池内把 top-5 种子的邻居提到前面（只重排） |
| `graph_open` | 用种子的邻居**替换**第 6–10 名（允许池外候选） |
| `graph_fuse` | 标准分数融合：`score = bm25 + λ·best_seed_score`，λ=0.5 **先验固定，未在测试集上调** |
| `graph_fuse_precise` | 同上，但只用能确定解析的边（local/import/unique/suffix，占 46%） |

| 臂 | r@1 | r@5 | r@10 | 文件 r@10 | Δ r@10（95% CI, p） |
| --- | ---: | ---: | ---: | ---: | --- |
| text | 0.091 | 0.214 | 0.275 | 0.624 | —— |
| graph_rerank | 0.103 | 0.217 | 0.287 | 0.614 | +0.012 (−0.026, 0.050, p=0.50) |
| graph_open | 0.091 | 0.214 | 0.257 | 0.576 | −0.018 (−0.051, 0.013, p=0.46) |
| graph_fuse | 0.091 | 0.217 | 0.272 | 0.624 | −0.003（p=1.00） |
| graph_fuse_precise | 0.091 | 0.217 | 0.275 | 0.624 | 0.000（p=1.00） |

**三条结论**

1. **在 10 槽预算下，没有任何一条图臂显著改善符号级定位**；分数融合（最标准的做法）在 λ=0.5 下几乎是一个恒等变换，PPR 也只是把第 1 槽从 0.091 提到 0.106（见 §5.2）。
2. **激进扩散显著伤害文件级**：`graph_open` 的文件 recall@10 掉了 **4.8 个点**（4 胜 18 负，p=0.004），PPR 掉 4.5 点（p=0.019）。原因是文件级本来就好，拿槽位换邻居是在丢价值。
3. **上限解释了大部分**：一跳 11.9% / 二跳 35.7% / 池召回（top-200）60.0% / 池召唤在 top-500 可达 70.4%。**候选生成不是硬天花板**（放大池子就能涨），而**可达上限 + 槽位兑换率**共同封顶（§5.2）。

> ⚠️ **覆盖率 1.000 不是发现，是自检。** 黄金符号和建图器共用 `模块.符号` 这套 id 口径，本来就该全中。它证明分母分子对得上，**不能当论文结论**。

**分仓库（符号级 r@10，text → graph_open）**：astropy 0.458→0.792（唯一明显受益）、django 0.292→0.273、sympy 0.203→0.203、matplotlib 0.283→0.175、scikit-learn 0.261→0.246、sphinx 0.281→0.250、pytest 0.250→0.188。**收益集中在图小、issue 与代码命名对不上的仓库**——正好是一跳可达率高、或图本身小的仓库，与解释一致。

### 5.1 消融（290 任务，与主实验同一批快照）

| 旋钮 | 取值 | 结果 |
| --- | --- | --- |
| 候选池 | 60 / 200 / 500 | 池召回 0.464 / 0.600 / **0.704**——**候选生成随池子增长**，不是硬天花板 |
| 种子数 | 1 / 3 / 5 / 10 | 一跳可达 0.038 / 0.089 / 0.119 / 0.118 |
| 跳数 | 1 / 2 | 二跳可达 **0.357**（≫ 一跳），但二跳臂 r@10 = 0.249（−0.026）**仍然输** |
| 融合权重 λ | 0.25 / 0.5 / 1.0 | r@10 = 0.272 / 0.272 / 0.199（λ=1.0 崩） |
| 扩散臂（1 跳） | 种子 1 / 3 / 5 / 10 | −0.027 / −0.037 / −0.018 / 0.000（10 种子=没位置换，退化） |

**最有价值的一行是「二跳可达 35.7% 但仍输」**：它证明瓶颈不是半径不够，而是**转化**——邻居里绝大多数不是答案，10 个槽位经不起赌。

**「图唯一能赢的交集」只有 1.4%**：80 个任务（27.6%）的黄金符号进不了 top-500 池，其中只有 4 个能被 top-5 种子一跳碰到。"文本失败"且"图相邻"同时成立极罕见。

> **一处已修正的错误**：早期版本报"一跳可达 22.1%"，是因为把**本身就是种子的黄金符号**也算成了"可达"（它只是与另一个种子相邻）。那是文本的功劳，不该记在图上。修正后为 11.9%。这条错误是靠消融与主实验交叉核对发现的。

### 5.2 扩散臂与「兑换率」（290 任务，`data/experiment_v3.jsonl`，`tools/analyse_v3.py`）

| 臂 | r@1 | r@5 | r@10 | 文件 r@10 | Δ r@10（p） |
| --- | ---: | ---: | ---: | ---: | --- |
| text | 0.091 | 0.214 | 0.275 | 0.624 | —— |
| **graph_ppr** | **0.106** | 0.214 | 0.268 | 0.579 | −0.007（p=0.72）；文件 **−0.045**（7 胜 20 负，p=0.019） |
| graph_ppr_text | 0.091 | 0.217 | 0.272 | 0.624 | −0.003（p=1.00） |

复核：`graph_open2` 在这一轮独立重算得 0.249，与消融里的二跳臂 0.249 完全一致，说明两条管线口径对得上。

**为什么"可达但不转化"这句话要改写成"上限 + 兑换率"：**

- 可达上限：38/290 任务（13.1%；41/354 符号）的黄金符号在 top-5 种子的一跳内；两跳 111 任务、125 符号。**即使转化率 100%，一跳臂最多也只能拿 +11.9 点**。
- 转化其实不差：41 个可达符号里，PPR 把 **18 个（44%，中位秩 12）**排进前 10。
- 但兑换是要付钱的：PPR 净收益 = **+15 找到，−17 丢掉 = −2**；`graph_open` 是 +12/−17。
- 兑换率本身：一跳球共 9,855 个邻居，其中 41 个是答案 = **0.42%**；文本 top-10 每槽 **3.1%** 是黄金。**约 7.5:1 的赔率**——图必须把球排得比文本排池子好七倍才不亏，PPR 恰好打成平手。

**预算放宽后唯一赢的是重排**：`graph_rerank` 在 k=20 时 +2.9 点（13 胜 3 负，p=0.021），k=50 时 +0.8（p=0.45）。它**只能重排、不能扩池**，所以收益只在槽位够多时才兑现——这正好从反面印证"扩池才是难的那一半"。

### 5.3 File-first 与乘积分解（290 任务，`data/experiment_ff.jsonl`，详见 [file-first.md](file-first.md)）

| 臂 | r@1 | r@5 | r@10 | 文件 r@10 | Δ r@10（p） |
| --- | ---: | ---: | ---: | ---: | --- |
| text | 0.091 | 0.214 | **0.275** | 0.624 | —— |
| ff_k1 / ff_k2 / ff_k3 | 0.091 | 0.198 / 0.211 / 0.204 | 0.236 / **0.268** / 0.257 | 0.328 / 0.459 / 0.503 | −0.039 / −0.007 / −0.018（均不显著） |
| ff_k5 | 0.091 | 0.168 | 0.241 | 0.586 | −0.034（p=0.078） |
| ff_graph | 0.091 | 0.159 | 0.237 | **0.638** | −0.038（**p=0.029**，显著更差） |
| file_oracle（诊断） | 0.215 | 0.499 | **0.665** | 1.000 | +0.390（p=0.000，125 胜 0 负） |

**乘积分解**（r@10 ≈ P(文件找到) × 条件回收率，每行误差 ≤0.014）：

| 每文件槽位 | 10 / 5 / 3.3 / 2 / 1.3 |
| --- | --- |
| P(文件找到) | 0.290 / 0.459 / 0.503 / 0.586 / 0.624 |
| 条件回收率 | 0.767 / 0.584 / 0.511 / 0.411 / 0.441 |
| 乘积（实测） | 0.222 / **0.268** / 0.257 / 0.241 / **0.275** |

三点：**①** 正确文件下 10 槽能捞 66.5%（2.4×），符号级本身不稀缺；**②** 文件 top-1 命中率只有 29%（k=3 才 50.3%，MRR 0.436），窄处不够准；**③** 所有分配都落在同一条曲线，正文的"广度"配置恰好在其最优端。图扩到文件级（`ff_graph`）买到最高文件召回 0.638，但符号级最低 0.237——**邻居增加的是广度，而缺的是深度**。

## 6. 这篇论文到底是哪一类

评审会问「所以呢」。三个能站住的落点：

1. **Best New Resource**：300 任务 / 354 个黄金符号的**符号级**基准 + 可复现流水线。现有基准（SWE-bench 系）只给文件和测试，没人给「参考修复动过哪几个符号」。这是 v5 最现实的目标。
2. **测量结论**：文件级 62.4% 与符号级 27.5% 的 2.3 倍差，说明 repo-level agent 的「已接近解决」是刻度问题。
3. **负结果 + 机制**：四种图策略无收益，且能用「可达但不转换」解释——不是「我们没做好」，是「多出来的邻居绝大多数是错的」。同时给出 46% 边解析率，说明大家手里的图本身半数是猜的。
